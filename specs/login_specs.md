# Login / Registration — Architecture & Implementation Spec

## Overview

Phone-number-based authentication with OTP verification, backed by **Firebase Auth**. New users complete a one-time registration form after their first successful OTP verification. The collected profile data is persisted in **Cloud Firestore**.

---

## Tech Stack

| Concern | Choice |
|---------|--------|
| Authentication | Firebase Auth — Phone / SMS OTP |
| Database | Cloud Firestore |
| State management | `provider ^6.1.2` (`ChangeNotifier`) + `flutter_riverpod ^2.6.1` (scheduling) |
| Phone field UI | `intl_phone_field ^3.2.0` |
| Date formatting | `intl ^0.20.2` |
| Navigation | Declarative flow-based (nested Navigators swapped reactively by `AuthWrapper`) |

```
Cold start
    │
    ▼
AuthWrapper (StreamBuilder on authStateChanges)
    ├── No Firebase user  ──────────────────────► AuthFlow (PhoneLoginScreen)
    │
    └── Firebase user exists
          │
          └── StreamBuilder: UserService().userStream(uid)
                ├── Profile found   ──────────► MainAppFlow (role-based screen)
                └── No profile      ──────────► RegistrationFlow (RegisterScreen)

    │  user enters phone number (country code + number)
    │  tap "Send OTP"
    ▼

    │  On success: AuthWrapper reactively swaps flow (no manual navigation)
    │
    └── OTP valid → Firebase auth state changes → AuthWrapper reacts


RegisterScreen
    │  First Name*, Last Name*, Email, Gender*, DOB*, Clinic
    │  tap "Complete Registration"
    │  profile saved to Firestore
    ▼
AuthWrapper detects profile via userStream → swaps to MainAppFlow


MainAppFlow (role-based routing)
    ├── admin     → AdminHomeScreen
    ├── therapist → TherapistHomeScreen
    └── patient   → PatientHomeScreen
```

## Data Model

### `UserModel`  _(lib/models/user_model.dart)_

**Firestore collection:** `users/{uid}`

| Field | Firestore key | Type | Notes |
|-------|--------------|------|-------|
| User ID | _(document ID)_ | `String` | Firebase Auth UID |
| Clinic ID | `clinicId` | `String` | Mapped from demo clinic name |
| Mobile Number | `phoneNumber` | `String` | E.164 format, e.g. `+919876543210` |
| First Name | `firstName` | `String` | Required |
| Last Name | `lastName` | `String` | Required |
| Email | `email` | `String?` | Optional |
| Gender | `gender` | `String` | `"male"` / `"female"` / `"other"` |
| DOB | `dob` | `Timestamp` | Date of birth |
| Role | `role` | `String` | `"patient"` (hardcoded for now) |
| Status | `status` | `String` | `"active"` (default on registration) |
| Created At | `createdAt` | `Timestamp` | Set once on registration |
| FCM Tokens | `fcmTokens` | `List<String>` | Device tokens for push notifications |

```dart
// lib/models/user_model.dart
class UserModel {
  final String uid;
  final String clinicId;
  final String phoneNumber;
  final String firstName;
  final String lastName;
  final String? email;
  final String gender;
  final DateTime dob;
  final String role;
  final String status;
  final DateTime createdAt;
  final List<String> fcmTokens;

  String get fullName => '$firstName $lastName';
}
```

Serialization helpers: `UserModel.fromMap(uid, map)` and `toMap()`.

## Service Layer

### `AuthService`  _(lib/services/auth_service.dart)_

Thin wrapper around `FirebaseAuth.instance`. Exposes:

```dart
Stream<User?> get authStateChanges
User?         get currentUser
Future<void>  verifyPhoneNumber({...callbacks})
Future<UserCredential> signInWithCredential(credential)

```

> **Why a wrapper?** Keeps providers testable — inject a mock `AuthService` in tests without touching Firebase.

## State Management

### `AuthProvider`  _(lib/providers/auth_provider.dart)_

Extends `ChangeNotifier`. Single source of truth for auth state.

#### `AuthStatus` enum

```dart
enum AuthStatus { idle, loading, codeSent, authenticated, error }
```

#### Public surface

| Member | Type | Description |
|--------|------|-------------|
| `status` | `AuthStatus` | Current state |
| `errorMessage` | `String?` | Last error, if any |
| `currentUser` | `UserModel?` | Profile loaded from Firestore |
| `firebaseUser` | `User?` | Raw Firebase user |
| `sendOTP(phone)` | `Future<void>` | Initiates SMS verification |
| `verifyOTP(code)` | `Future<void>` | Signs in; AuthWrapper handles routing reactively |
| `register(...)` | `Future<void>` | Writes profile to Firestore (includes `status: 'active'`) |
| `loadCurrentUser()` | `Future<void>` | Loads profile from Firestore |
| `signOut()` | `Future<void>` | Signs out + resets state |
| `clearError()` | `void` | Resets error state |

#### State transitions

```
idle
 │  sendOTP()
 ▼
loading ──onFailed──► error
 │
 │  onCodeSent
 ▼
codeSent
 │  verifyOTP()
 ▼
loading ──exception──► error
 │
 └── sign-in succeeds ──► authenticated
     (AuthWrapper detects authStateChanges + profile stream → swaps flow)

idle (on RegisterScreen)
 │  register()
 ▼
loading
 │  Firestore write succeeds
 ▼
authenticated (_currentUser set)
(AuthWrapper detects profile via userStream → swaps to MainAppFlow)
```

#### Android auto-verification

`_handleAutoVerification(PhoneAuthCredential)` is passed as `onAutoVerified` to Firebase. It calls `signInWithCredential` and sets status to `authenticated`. AuthWrapper reacts to `authStateChanges()` and handles routing — no manual navigation needed in the OTP screen.

#### Navigation architecture

The app uses a **declarative flow-based** approach with nested Navigators. `AuthWrapper` reactively swaps between three flows:
- `AuthFlow` — login + OTP screens
- `RegistrationFlow` — register screen
- `MainAppFlow` — role-based home screens

This eliminates double-navigation issues and `pushAndRemoveUntil` complexity. Screens never navigate to other flows; `AuthWrapper` swaps the entire widget tree based on auth state + profile existence.

## Screen Details

### `PhoneLoginScreen`

- `IntlPhoneField` with default country `IN`; stores `phone.completeNumber` (E.164)
- Validation via `Form` + `GlobalKey<FormState>`
- Calls `provider.sendOTP(...)` → on `codeSent` pushes `OtpVerificationScreen`

### `OtpVerificationScreen`

- 6 individual `TextField` boxes; focus auto-advances on digit entry, retreats on backspace
- Auto-submits when all 6 digits are filled
- 60-second countdown timer; "Resend OTP" button enabled after expiry
- Listens to provider via `addListener` / `removeListener` for Android auto-verification
- On success: AuthWrapper reactively detects auth state change and swaps flow (no manual navigation from this screen)

### `RegisterScreen`

- `TextFormField` for First Name* (required, min 2 chars) and Last Name* (required, min 2 chars)
- `TextFormField` for Email (optional, regex validated)
- `DropdownButtonFormField` for Gender* (`Male`, `Female`, `Other`)
- Date picker for DOB* (via `showDatePicker`)
- `DropdownButtonFormField` for Clinic (optional) — 3 demo clinics with hardcoded IDs
- Role is hardcoded to `"patient"`, status is set to `"active"`
- No back navigation (`automaticallyImplyLeading: false`)
- Calls `provider.register(...)` → Firestore write → AuthWrapper detects profile via `userStream` → swaps to `MainAppFlow`

### Role-Based Home Screens

After successful login/registration, `MainAppFlow` routes by `user.role`:
- **Admin** → `AdminHomeScreen` — scheduling dashboard with FAB for new plans
- **Therapist** → `TherapistHomeScreen` — today's + upcoming sessions
- **Patient** → `PatientHomeScreen` — active plans + upcoming sessions

## `AuthWrapper`  _(main.dart)_

Handles cold-start and session-restore with reactive Firestore profile stream. Wrapped in `ProviderScope` for Riverpod (scheduling features).

```dart
StreamBuilder<User?>(authStateChanges)
  ├── waiting       → _SplashLoader
  ├── user == null  → AuthFlow (nested Navigator → PhoneLoginScreen)
  └── user != null  → StreamBuilder<UserModel?>(UserService().userStream(uid))
        ├── waiting    → _SplashLoader
        ├── hasProfile → MainAppFlow(user: profile)  // role-based routing
        └── noProfile  → RegistrationFlow (nested Navigator → RegisterScreen)
```

**Debug mode**: `appVerificationDisabledForTesting: true` is set so Firebase test phone numbers work on emulators without Play Services.

## Error Handling

All Firebase error codes are mapped to human-readable messages inside `AuthProvider._mapAuthError`:

| Firebase code | Message shown |
|---------------|---------------|
| `invalid-phone-number` | "The phone number entered is invalid." |
| `too-many-requests` | "Too many attempts. Please try again later." |
| `invalid-verification-code` | "Invalid OTP. Please check and try again." |
| `session-expired` | "OTP session has expired. Please request a new one." |
| _(other)_ | Raw `e.message` or generic fallback |

Errors surface as `SnackBar` in screens. After showing, `provider.clearError()` is called to avoid re-displaying on rebuild.

## Firebase Console Setup Checklist

- [ ] **Authentication → Sign-in method → Phone** — enabled
- [ ] **Firestore Database** — created (start in test mode, then add rules)
- [ ] **SHA-1 / SHA-256 fingerprints** added to the Android app in Firebase Console (required for OTP on Android)

### Recommended Firestore security rules

```js
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```
